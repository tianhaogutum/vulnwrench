# vulnwrench triage

Scanner exceptions usually live in three places at once: a `.trivyignore.yaml`, an
`osv-scanner.toml` and an OpenVEX document, each with its own idea of owners, expiry and
scope. `vulnwrench triage` keeps them in **one typed decision file** and compiles it into
all three, with a conversion report that lists exactly what each target cannot express.
Use it when you need reviewable, expiring exceptions in CI, a renewal plan before they
lapse, or a careful import of an existing Trivy ignore file.

_Formerly the standalone `triage-bridge` tool._

**An ignore is not evidence that a product is unaffected.** `accepted_risk` never
becomes `not_affected`. Package-specific exceptions cannot be represented by OSV's
ID-only `IgnoredVulns`: compilation fails unless you explicitly accept that scope
widening. Every supplied decision is an instruction to suppress scanner findings,
including `affected` and `under_investigation`; the VEX projection preserves those
statuses. Review the report before using any generated configuration.

## Quick start

Standard library only; nothing is downloaded and no scanner runs. From a clone of the
repository:

```sh
pip install vulnwrench
vulnwrench triage --help

# Validate and print the conversion report without writing files
vulnwrench triage compile examples/triage/decisions.json \
  --as-of 2026-11-11 --author 'Synthetic Example Team' \
  --product-id urn:example:demo-product:1.0 \
  --timestamp 2026-11-11T12:00:00Z --dry-run --allow-scope-loss

# Write .trivyignore.yaml, osv-scanner.toml, openvex.json and conversion-report.json
vulnwrench triage compile examples/triage/decisions.json \
  --as-of 2026-11-11 --author 'Synthetic Example Team' \
  --product-id urn:example:demo-product:1.0 \
  --timestamp 2026-11-11T12:00:00Z --out-dir out --allow-scope-loss

# Which exceptions expire soon or changed owner? Exit 1 if any need review
vulnwrench triage preview-renewal examples/triage/renewal/prior.json \
  --prior-as-of 2026-11-01 --current examples/triage/renewal/current.json \
  --as-of 2026-11-11 --expiring-within-days 7 --format markdown --fail-on-review

# Turn an existing Trivy ignore file into decision drafts for human review
vulnwrench triage import-trivy examples/triage/import-trivy/native.trivyignore.yaml
```

| Subcommand | What it does |
| --- | --- |
| `compile` | Compile strict JSON decisions into a new directory, or validate with `--dry-run` |
| `preview-renewal` | Print a review-only renewal plan; never renews or compiles exceptions |
| `import-trivy` | Print decision drafts from supported native Trivy ignore YAML; requires human review |
| `finalize-import` | Validate an explicit native-import review and print decisions with source references |

The decision input format is described by
[`triage/schemas/decisions-v1.schema.json`](triage/schemas/decisions-v1.schema.json).
Generated files and reports keep the identifiers the standalone tool wrote
(`"tool": "triage-bridge"`, `urn:triage-bridge:` source references and the
`# Generated by triage-bridge` TOML header), so saved reports stay verifiable.

## Synthetic CLI example

The fixtures contain invented IDs and packages and make no real exploitability
claims. From the root of a repository clone, this command **fails with exit 2** and creates no
output, because OSV would widen the package scope:

```sh
vulnwrench triage compile examples/triage/decisions.json \
  --as-of 2026-11-11 --author 'Synthetic Example Team' \
  --product-id urn:example:demo-product:1.0 \
  --timestamp 2026-11-11T12:00:00Z --out-dir out
```

After reviewing that loss, explicitly allow it:

```sh
vulnwrench triage compile examples/triage/decisions.json \
  --as-of 2026-11-11 --author 'Synthetic Example Team' \
  --product-id urn:example:demo-product:1.0 \
  --timestamp 2026-11-11T12:00:00Z --out-dir out --allow-scope-loss
```

Actual CLI stdout for that synthetic example:

```json
{"counts": {"decisions": 1, "osvEntries": 1, "trivyEntries": 1, "vexStatements": 1}, "files": [".trivyignore.yaml", "conversion-report.json", "openvex.json", "osv-scanner.toml"], "losses": 5}
```

Actual generated OSV configuration:

```toml
# Generated by triage-bridge; inspect conversion-report.json before use.
# Package scope was explicitly widened. This is scanner suppression, not VEX proof.

[[IgnoredVulns]]
id = "CVE-2025-0001"
reason = "Investigation"
effectiveUntil = 2026-12-01
```

The four generated files are checked in under
[`examples/triage/expected/decisions/`](../examples/triage/expected/decisions/).
[`examples/triage/mixed-decisions.json`](../examples/triage/mixed-decisions.json) covers all five
statuses, one explicit alias, VEX justifications and remediation actions. Its
actual output under [`examples/triage/expected/mixed-decisions/`](../examples/triage/expected/mixed-decisions/)
has six scanner-ignore entries and four VEX statements. These are generated CLI
artifacts, not hand-written representative output.

Compile input must resolve to a **readable regular file**. The CLI opens it with
`O_NONBLOCK`, checks the opened descriptor's type before reading at most 2 MiB + 1
bytes, and closes it on success or refusal. Final and ancestor symlinks to regular
files are supported on the trusted local filesystem. FIFOs (with or without a
held peer), links to FIFOs, sockets, directories, devices and missing, dangling or
unreadable paths fail promptly with redacted `E_IO`, exit 2, empty stdout and no
new output directory. The existing 2 MiB UTF-8 JSON, duplicate-key, non-finite-number
and nesting checks still apply. Argument structure is checked first, then input
read/type/JSON, then strict decisions, dates, expiry and scope-loss authorization,
then output publication. Invalid input therefore wins over invalid compiler dates
or output paths. Regular inputs retain the same stdout and artifact bytes.
Nonblocking open avoids FIFO rendezvous; it does not bound filesystem latency or
provide an atomic snapshot against concurrent writers. Reads may update access
times. The library's `load_document(FILE, regular_only=False)` default retains its
existing policy. Compile, renewal and finalization explicitly opt into
`regular_only=True`. Native import uses the same policy through its own loader,
described below.

The output directory must be **new**, its parent must already exist, and no path
component may be a symlink or `..`. Existing directories/files are never replaced,
even when their contents happen to match. Files are created mode 0600 inside a
mode 0700 directory; the report retains complete decision details. On an ordinary
write failure, this invocation removes its own partial output. Publication is not
transactional for concurrent readers; use a trusted local filesystem.

### Validate without publishing (`--dry-run`)

`compile` requires **exactly one** of `--out-dir NEW_DIR` or `--dry-run`. Combining
them, or omitting both, is a redacted `E_ARGUMENT` with exit 2 and empty stdout,
before any input is read. `--dry-run` runs the same single pure compiler pass with
the same strict input, evidence, expiry, alias, overlap, metadata and OSV
scope-loss checks. On success it writes the complete `conversion-report.json` bytes
to stdout, flushes them, and exits 0. Required metadata flags and `--allow-scope-loss`
behave as before:

```sh
vulnwrench triage compile examples/triage/decisions.json \
  --as-of 2026-11-11 --author 'Synthetic Example Team' \
  --product-id urn:example:demo-product:1.0 \
  --timestamp 2026-11-11T12:00:00Z --dry-run --allow-scope-loss
```

For the same input and parameters, this stdout is byte-identical to the
`conversion-report.json` that `--out-dir` publishes. Without `--allow-scope-loss`
the command fails with exit 2 and empty stdout, as the publishing form does.
Validation refusals are redacted and print no report. A dry run creates no output
directory or files on success or failure, and does not change input file contents
or modes (access times may change).
Exit 0 means compilation validation only. It is not approval, provenance,
scanner evidence or a publication step.

Dry run still generates the artifacts **in memory** so the report can carry their
byte counts and SHA-256 values. It does not execute a scanner, call the compilation
writer or publish anything.

## Offline exception-renewal preview

Compare a saved **decision document v1** with a new UTC review date and, optionally,
a current candidate document. Give each record a stable, unique `decisionId` before
saving the baseline; reuse it when ownership or package scope changes. Optional
`sourceRefs` retain ticket/evidence references as opaque strings. Neither references
nor packages are fetched. Vulnerability `ids` remain independent of `decisionId`.

The local synthetic fixtures define six outcomes and contain no real security
assertions. This prints a full JSON review plan to stdout and creates no files:

```sh
vulnwrench triage preview-renewal examples/triage/renewal/prior.json \
  --current examples/triage/renewal/current.json \
  --prior-as-of 2026-11-01 --as-of 2026-11-11 --expiring-within-days 7
```

Expected `statuses`, in prior document order: `expired`, `expiring_soon`,
`owner_changed`, `owner_missing`, `scope_changed`, `unchanged`. The plan has six
decisions, five requiring review, and `automaticActions: []`. The full actual output
is saved in [`examples/triage/renewal/expected-plan.json`](../examples/triage/renewal/expected-plan.json).
Omit `--current` for a date-only review of the saved decisions. `--prior-as-of` is
an explicit caller-supplied baseline date; a review cannot go backwards from it.

Expiry is the **first invalid UTC day**: `expiresOn <= --as-of` is `expired`.
`expiring_soon` means 1 through `--expiring-within-days` days remaining, inclusive
(default 30, range 0–3660); otherwise `expiryStatus` is `active`. `expiryStatus`
always describes the prior exception, or the current one for an added decision.
`currentExpiryStatus` independently describes the candidate. Extending a candidate's
expiry never clears the prior `expired` finding; shortening it adds
`current_expired`/`current_expiring_soon` when different from the prior finding.

Statuses accumulate: missing owners, owner handoffs, changed primary IDs/aliases or
exact PURL scope, changed policy/evidence, changed source references, and added or
removed decisions all get separate findings and human review actions. `unchanged`
means active, outside the review horizon, with none of those changes. Matching uses
only `decisionId`; IDs are never guessed from package scope or vulnerability names.
Added decisions follow the prior entries in current-document order. Reordering
records alone does not constitute a change.

Both source records, vulnerability IDs, supplied references, source document digests
and JSON pointers are retained in each plan entry. Missing/null/empty owners (also
spaces, LF or TAB only) are `owner_missing` in previews; compilation still requires
valid owners. All other decision validation remains in force. Missing/duplicate
decision IDs, invalid documents (including an explicitly null current document),
invalid dates or a backwards date fail with exit 2, redacted diagnostics and empty
stdout. Each document still requires 1–10,000 records; an empty current bundle is
not supported. By default every valid preview exits 0, even when review is needed.

For CI, add `--fail-on-review` to the same invocation:

```sh
vulnwrench triage preview-renewal examples/triage/renewal/prior.json \
  --current examples/triage/renewal/current.json \
  --prior-as-of 2026-11-01 --as-of 2026-11-11 --expiring-within-days 7 \
  --fail-on-review
```

This prints the **byte-identical complete ordinary plan** and exits **1** because
its existing `counts.reviewRequired` is five. With the flag, a zero review-required
count exits **0**. The flag uses that count directly: every existing review reason,
including added/removed decisions, still requires human attention; an active
unchanged plan does not. A candidate expiry extension cannot clear an expired prior
exception or its gate. The flag does not approve, renew or suppress anything.
It also works with conversion-report baselines and either or both verification
opt-ins. All requested baseline/current/source/artifact validation must succeed
before any stdout or gate evaluation. Invalid or unverifiable inputs still exit
**2** with redacted diagnostics and empty stdout, regardless of the flag.
The complete selected format is written and stdout flushed before the gate returns. Output
write/flush exceptions retain Python's stream-error behavior and take precedence
over a gate return; a failed stream cannot guarantee complete or retractable output.

For human review, select `--format markdown` (`--format json` is the unchanged
default):

```sh
vulnwrench triage preview-renewal examples/triage/renewal/prior.json \
  --current examples/triage/renewal/current.json \
  --prior-as-of 2026-11-01 --as-of 2026-11-11 --expiring-within-days 7 \
  --format markdown --fail-on-review
```

This prints a deterministic Markdown report and exits **1**, using the same five
review-required decisions as JSON. The renderer consumes the completed plan after
all requested verification; it does not compile, verify again, change matching or
select a subset of findings. Tables show dates/horizon/counts, `automaticActions: []`,
every decision in plan order, separate prior/current expiry dates and states,
all accumulated statuses and human review actions. A missing side is `absent`;
the prior expiry cell of an added decision stays absent even though that entry's
JSON `expiryStatus` describes its current record. Candidate extensions cannot hide
prior expiry or clear the gate. Active unchanged entries have no requested actions.
Evidence tables preserve both source digests/pointers/decision indices, archived
source digests/pointers for report baselines, opaque source references and either
independent verification result. Unselected checks say `not requested`.

All arbitrary table values are inert code spans with JSON-style visible escaping.
Newlines/tabs and literal backslashes remain distinguishable; pipes, backticks,
angle brackets and Unicode control/format/line-separator characters are escaped
as Unicode sequences. Ordinary Unicode text is retained. Opaque references are
never fetched or turned into links. The full-plan appendix is lossless, ASCII
escaped JSON inside a backtick fence longer than any backtick run in its content.
It retains **all copied prior/current records**, including owner, reason, status,
policy/evidence text and source references, plus digests and verification results.
**It is not redacted: control who receives the report.** Escaping makes presentation
inert; it does not conceal sensitive record evidence. The plan still makes no new
security or provenance assertion.

Both formats preserve the same 0/1/2 exit rules, full validation and regular-file
input policy. Invalid format names fail `E_ARGUMENT` before any file is read.
Invalid documents, dates, reports or requested verification produce no partial
Markdown and retain redacted exit-2 errors with or without the gate. Output stream
write/flush failures retain the behavior described above. No files are created by
preview; shell redirection or sharing the report is the caller's separate action.

The baseline file (decisions or conversion report) and optional `--current` file
must resolve to **readable regular files**. Each uses `O_NONBLOCK` open, checks the
opened descriptor's type before reading at most 2 MiB + 1 bytes, and closes it on
success or refusal. Final or ancestor symlinks to regular files are allowed on the
trusted local filesystem. FIFOs, including those without a writer or with a peer
holding them open, links to FIFOs, sockets, directories, devices and unreadable or
dangling paths fail promptly with redacted `E_IO`, exit 2 and empty stdout.
The existing 2 MiB UTF-8 JSON, duplicate-key, non-finite-number and nesting checks
still apply. Nonblocking open avoids FIFO rendezvous; it does not bound filesystem
latency or provide an atomic snapshot against concurrent writers. Reads may update
access times; preview changes no contents, modes or directory entries.

Validation order is explicit: command/verification-option checks run before input
reads; the baseline is read and decoded, then the optional current document. Only
then does review validate report consistency, dates and decisions. Optional original
source verification follows a valid review, then optional artifact verification;
stdout is printed only after all requested checks succeed. The optional review gate
is evaluated after the complete plan is written and flushed. A baseline/current
file error therefore precedes optional verification, while an invalid verification
option with a decision baseline fails `E_ARGUMENT` before reading any file.

The plan never changes dates, approves exceptions, writes scanner suppression or
issues OpenVEX statements. Explicit VEX statuses may appear only inside copied
source records; the preview makes no new `not_affected` assertion. A plan is not
compiler input. Compiling the original expired bundle still fails `E_EXPIRED`, with
no output directory; existing static scanner/VEX files require external withdrawal.
Native scanner/config imports are not supported by this command.

## Review a saved compilation report

A saved `conversion-report.json` can replace the baseline decision document:

```sh
vulnwrench triage preview-renewal examples/triage/renewal/conversion-report.json \
  --prior-format conversion-report --current examples/triage/renewal/current.json \
  --as-of 2026-11-11 --expiring-within-days 7
```

This checked-in report was compiled from the synthetic renewal baseline on
`2026-11-01`. The command prints the same six outcomes as the decision-document
example: `expired`, `expiring_soon`, `owner_changed`, `owner_missing`,
`scope_changed`, `unchanged`; counts are six decisions and five requiring review.
By default it reads only the report and the optional candidate. Omit `--current`
to review only the archived records by date. No sibling artifacts or original
decision file are needed or read without their respective verification opt-ins below. Stdout is a review plan with
`automaticActions: []`; no scanner/VEX files are emitted.

`--prior-format` defaults to `decisions`; wrappers are never guessed. Report mode
supports **complete schema v1 compilation reports** (`"tool": "triage-bridge"`, `"toolVersion": "0.1.0"`, the format identifiers this command keeps writing)
with normalized records, all metadata and 1–10,000 decisions. It validates strict
record policy/evidence, archived date/timestamp, mappings, losses, counts,
omissions, warnings and expected artifact hashes/byte lengths by reproducing the
supported compiler output in memory. This consistency validation alone does not
inspect saved artifact bytes.
Report input has the same 2 MiB UTF-8 JSON limit, duplicate-key rejection and
non-finite-number rejection as decision input. Large compiler outputs exceeding
that input limit cannot currently be imported.

The baseline date comes from `parameters.asOf`. Optional `--prior-as-of` must
match it; review cannot go backwards. Records must have been valid on the archived
compilation date, but can now be expired. Every record still needs an explicit,
unique `decisionId`; a valid legacy report without these IDs fails
`E_RENEWAL_ID`. No identity is inferred. `--current` continues to accept only a
v1 decision document and can have missing owners for review.

Report rows may be reordered, but archived `index` values must be unique integers
covering exactly `0..N-1`; missing, duplicate, negative, boolean or out-of-range
indices are errors. Plans follow report-array order. Each prior entry retains:

- `source.canonicalJsonSha256`: digest of the supplied report's canonical JSON.
- `source.pointer`: `/decisions/POSITION/record`, locating that record in the report.
- `source.decisionIndex`: the archived index, independent of array position.
- `source.archivedSourceCanonicalJsonSha256` and `archivedSourcePointer`: the
  original decision-document digest and `/decisions/INDEX`.

`sources.priorArchivedSourceCanonicalJsonSha256` also retains the original digest.
Without a current document, both sides reference the same report and retain the
same archived provenance. Original input cannot be reconstructed exactly from
normalized records, so its digest is validated as 64 lowercase hexadecimal
characters and copied, **not independently verified unless `--verify-source` is supplied**. Content hashes and report
consistency do not authenticate authorship or security assertions.

Unknown versions/fields, malformed indices/digests, incomplete reports, invalid
records or inconsistent metadata fail with redacted `E_REPORT` diagnostics, exit
2 and empty stdout. Invalid JSON/encoding/size fails `E_INPUT`; unreadable files
fail `E_IO`; invalid, conflicting or backwards review dates fail `E_DATE`. Reports
and review plans remain invalid compile input. This import does not approve or
renew policy, publish VEX or withdraw existing artifacts.

To additionally check saved compilation **payload bytes**, opt in with an explicit
local directory. For a generated synthetic bundle:

```sh
vulnwrench triage compile examples/triage/renewal/prior.json \
  --as-of 2026-11-01 --author 'Synthetic Example Team' \
  --product-id urn:example:demo-product:1.0 \
  --timestamp 2026-11-01T12:00:00Z --allow-scope-loss --out-dir archived-out
vulnwrench triage preview-renewal archived-out/conversion-report.json \
  --prior-format conversion-report --verify-artifacts archived-out \
  --current examples/triage/renewal/current.json --as-of 2026-11-11 --expiring-within-days 7
```

Only after every listed payload matches its report SHA-256 **and byte length**,
the same plan gains `artifactVerification: {"status": "verified", "artifacts":
{...}}`, with each checked filename mapped to its `sha256` and `bytes`. The six
outcomes, five required reviews, archived indices and report/original-source
content digests are retained; expired findings remain expired. Paths and read times
are not included, so fixed inputs produce the same plan. Without the opt-in this
field is absent and standalone-report behavior is unchanged.

The exact payload names are `.trivyignore.yaml`, `osv-scanner.toml` and
`openvex.json`. The directory must contain every payload in the validated report
and no unlisted supported payload; a stray `openvex.json` fails when the report
omits VEX for accepted risk. Unrelated entries are ignored and never opened or
traversed. `conversion-report.json` is an optional sidecar, not a self-hashed
payload: only the explicitly selected baseline report is read, and it may live
elsewhere. Verification does not compare a second report in the artifact directory.

This option requires `--prior-format conversion-report`; using it with decisions
fails `E_ARGUMENT`. Report consistency validation still runs first. The artifact
directory must exist, have no `..` component and have no symlink in any explicit
path component. Payloads must be regular files, with no symlinks (even to matching
bytes), directories, FIFOs, sockets or devices. Hard links to regular files are
allowed. Reads use directory-relative descriptors, refuse symlinks and use
nonblocking open before type checks. Size must match before reading; SHA-256 is
streamed in chunks of at most 64 KiB, reading at most the expected byte length plus
one, without loading the whole saved artifact. File metadata and supported-name
membership are checked before and after reading to detect changes.

Missing, altered, too short/long, unexpected supported, unreadable or unsafe
artifacts fail with **exit 2**, redacted `E_ARTIFACT` diagnostics and empty stdout.
No plan is printed on failure. Verification intentionally changes no file contents,
modes or directory entries; filesystem access times may change on reads. This is
Linux/POSIX trusted-local-filesystem verification, not an atomic snapshot or a
guarantee against concurrent malicious writers. The selected report remains
caller-supplied: matching bytes and consistent metadata are **not signatures,
authenticated origin or independently verified security evidence**. The original
decision document digest remains retained without independent verification unless
the separate source check below is requested.

To additionally verify the **original decision document**, explicitly supply it:

```sh
vulnwrench triage preview-renewal archived-out/conversion-report.json \
  --prior-format conversion-report --verify-source examples/triage/renewal/prior.json \
  --verify-artifacts archived-out --current examples/triage/renewal/current.json \
  --as-of 2026-11-11 --expiring-within-days 7
```

`--verify-source FILE` and `--verify-artifacts DIR` are independent: either, both,
or neither may be requested. Both require `--prior-format conversion-report`;
using either with a decision baseline fails `E_ARGUMENT` before input reads.
The source is an original v1 decision document, not a report or review plan. It
uses the same bounded JSON reader: at most **2 MiB** UTF-8, no duplicate object
keys, non-finite numbers or unsupported parser nesting. Invalid JSON/encoding/size
fails `E_INPUT`; unreadable or nonregular source files fail `E_IO`, exit 2 with
empty stdout and redacted diagnostics. Source verification opens with `O_NONBLOCK`,
checks the **opened descriptor** is a regular file before reading, reads at most
2 MiB + 1 bytes, and closes it on success or refusal. FIFOs (including ones with
no writer or a peer holding them open), sockets, directories and character devices
are refused without waiting for stream input. Final or ancestor symlinks to
readable regular source files remain allowed on the trusted local filesystem;
dangling links and links to nonregular targets fail. The artifact directory's
nonsymlink policy is separate. This bounds input bytes and avoids FIFO rendezvous;
it does not bound filesystem latency or provide an atomic snapshot against
concurrent writers. Renewal baseline/current files use this same regular-file
policy. Compile, native import and finalization CLI inputs also use this policy.

After report and review validation, the source must pass **strict compilation at
the archived `parameters.asOf`**, with the archived author, product ID, timestamp
and scope-loss authorization. Owners and status evidence are required, overlaps
are rejected, and expiry must be after the archived date. A record can now be
expired and still verify; verification never clears its review finding.

SHA-256 of the original decoded document's canonical JSON must equal
`report.source.canonicalJsonSha256`. Canonical bytes use the compiler's existing
`json_bytes`: Python `json.dumps(ensure_ascii=False, sort_keys=True, indent=2,
allow_nan=False)`, followed by LF and UTF-8 encoding. JSON whitespace, object-key
order and equivalent escapes may differ. Array order and decoded values remain
significant. This is not RFC 8785/JCS and does not normalize decision records
before hashing: omitted `schemaVersion` (which defaults to v1) or `aliases` versus
explicit defaults can produce different digests for equivalent compiled policy.
Reconstructing normalized report records is insufficient to verify the original.

The source must also reproduce **every report field**, including normalized
records at their archived indices, mappings, losses, parameters and payload
hashes/lengths. Reordered report rows are matched by their validated archived
`index`; original decision array order is preserved. Even a matching digest in a
self-consistent report cannot substitute different source records. Invalid source
policy/format or a digest/content mismatch fails redacted `E_SOURCE`, exit 2 and
empty stdout. Invalid reports still fail `E_REPORT`. Nothing is printed if any
requested verification fails.

Only after success does the unchanged plan gain `sourceVerification`:
`{"status": "verified", "canonicalJsonSha256": "…", "decisionIndices": [0, 1, 2, 3, 4, 5]}`.
Indices follow report-array order, so reversing report rows returns `[5,4,3,2,1,0]`.
The result includes no paths or read times. Report and original digests, archived
pointers, candidate changes, expiry findings and `automaticActions: []` remain.
The pure library helper `verify_report_source(report, decoded_document)` returns
this result after the same checks, without I/O. Already-decoded objects retain the
compiler's 1–10,000-record and field limits; use
`load_document(FILE, regular_only=True)` for the CLI's regular-file,
nonblocking-open, byte-limit and duplicate-key checks. The keyword defaults to
`False` for existing library callers.

Verification intentionally changes no contents, modes or directory entries; reads
may update access times. The report, original, authorship, aliases and security
assertions are still caller-supplied. Matching original content is **not an
authenticated origin, signature or independently verified security evidence**.

## Import native Trivy ignores for review

`import-trivy` reads one local `.trivyignore.yaml` and prints a deterministic
draft report to stdout (JSON by default). It creates no files and performs no scanner or network
calls. The supported fields come from the supplied
[Trivy ignore-format documentation](https://trivy.dev/latest/docs/configuration/filtering/):
`vulnerabilities[].id`, `purls`, `statement`, and `expired_at`. This is a bounded
format importer, not a general YAML reader.

The CLI input must resolve to a **readable regular file**. It reuses the bounded
reader's `O_NONBLOCK` open and checks the opened descriptor's type before reading
at most 2 MiB + 1 bytes; the descriptor closes on success or refusal. Final and
ancestor symlinks to readable regular files are supported on the trusted local
filesystem. FIFOs (with or without a held peer), links to FIFOs, sockets,
directories, devices and missing, dangling or unreadable paths fail promptly with
redacted `E_IO`, exit 2 and empty stdout. No files are created. Regular inputs
retain identical draft JSON bytes, including raw-byte digests, source pointers,
unsupported findings and null owner/status fields. Nonblocking open avoids FIFO
rendezvous; it does not impose a deadline on filesystem latency or protect against
concurrent writers. Reads may update access times. This policy applies to the
import CLI and explicit `load_trivy_ignore(FILE, regular_only=True)` calls; the
library default is `False`. Finalization explicitly opts its three inputs into
this same policy, as described below.

```sh
vulnwrench triage import-trivy examples/triage/import-trivy/native.trivyignore.yaml
```

This synthetic fixture has two native entries. Expected output is **three draft
decisions**, zero unsupported entries, `mode: "review_only"`, and
`automaticActions: []`. The first entry expands its two exact versioned PURLs to
two records, preserving `CVE-2099-0062`, `Investigation: synthetic fixture`, and
`2026-12-01`. Each has `owner: null` and `status: null`. The second has no native
PURL or expiry, so its `package` and `expiresOn` also remain null. The complete
actual output is checked in as
[`examples/triage/import-trivy/expected-draft.json`](../examples/triage/import-trivy/expected-draft.json).

The report's `decisionDocument` uses v1 decision field names with explicit nulls
for missing required evidence. `reviews` lists each draft's `requiredFields`,
native source pointer, scope kind and package-scope review requirement. `source`
retains the input byte SHA-256 (including comments/whitespace); this identifies
content, not authenticated provenance. No owner, VEX status, aliases, reason or
expiry is invented. Missing native `statement` becomes a null `reason`.

For human review, select `--format markdown`; `--format json` explicitly selects
the unchanged default JSON bytes. Both formats accept the independent
`--fail-on-unsupported` gate:

```sh
vulnwrench triage import-trivy examples/triage/import-trivy/native.trivyignore.yaml \
  --format markdown --fail-on-unsupported
```

This supported example exits 0 and still requires review. Markdown displays every
draft in original order with its zero-based index, all copied decision fields,
explicit nulls, `requiredFields`, `reviewFields`, `reviewRequired`, `nativeScope`
and original source pointer. It includes the raw-byte source digest, counts, all
unsupported findings with original indices/pointers, and every warning. Empty and
all-unsupported reports explicitly show that there are no supported drafts.
The renderer presents exactly one completed import report; it does not infer
policy, approve drafts, compile outputs or alter native bytes.

Table values and warnings are inert code spans: backslashes and embedded
newlines/tabs use visible JSON escapes, and pipes, backticks, angle brackets and
Unicode control/format/line-separator characters are escaped. Opaque pointers
and source text are not fetched or linked. A dynamically fenced ASCII-escaped
**full draft JSON appendix** losslessly retains the entire report. **Disclosure:
it is not redacted** and includes all copied IDs, packages, reasons, dates, nulls,
review requirements, digests/pointers, unsupported findings and warnings. It does
not reconstruct rejected raw source values. Control who receives it. Markdown is
a review presentation, not compile input or a replacement for the unmodified JSON
draft/native bytes needed by `finalize-import`. Output may exceed the input size;
there is no pagination or redaction option.

**Review every draft before finalization or compilation.** Both
the report itself and an incomplete extracted document fail compilation with exit
2 and no output directory. Assign an owner, an explicit status and any required
status evidence; resolve all other null fields. Missing or empty native `purls`
means all packages in Trivy: the draft's null `package` cannot compile until a
reviewer chooses an exact versioned PURL. That choice **narrows** native scope;
it is not a lossless import of the original global rule. Dates are copied without
extension. The compiler still rejects expired dates and overlapping decisions,
requires `not_affected`/`affected` evidence, and requires explicit authorization
for the separate OSV scope loss.

For the fully supported exact-scope fixture, review adds only explicit synthetic
owners and `accepted_risk` statuses in
[`reviewed-decisions.json`](../examples/triage/import-trivy/reviewed-decisions.json):

```sh
vulnwrench triage import-trivy examples/triage/import-trivy/supported.trivyignore.yaml
vulnwrench triage compile examples/triage/import-trivy/reviewed-decisions.json \
  --as-of 2026-11-11 --author 'Synthetic Example Team' \
  --product-id urn:example:demo-product:1.0 \
  --timestamp 2026-11-11T12:00:00Z --allow-scope-loss --out-dir imported-out
```

The resulting Trivy file preserves the supported native ID/PURL/reason/expiry
tuples (one entry per PURL). It has three Trivy entries, two global OSV entries
and zero VEX statements. The test suite checks this round trip.

Unsupported selectors block the **whole native entry**, including entries mixing
supported and unsupported PURLs. `paths` (even empty), versionless/wildcard or
otherwise unsupported PURLs, unknown entry fields and invalid field values get
structured `unsupported` findings with source pointers and no draft for that
entry. Non-vulnerability sections are reported as unsupported. For example:

```sh
vulnwrench triage import-trivy examples/triage/import-trivy/unsupported.trivyignore.yaml
```

This returns a review report with **zero drafts** and an `unsupported_paths`
finding at `/vulnerabilities/0/paths`. By default, valid draft reports exit 0 even
when entries are unsupported; inspect `unsupported`, not only the exit code.
For CI, opt into the existing unsupported-finding count gate:

```sh
vulnwrench triage import-trivy examples/triage/import-trivy/unsupported.trivyignore.yaml \
  --fail-on-unsupported > draft.json
```

This prints the **same complete draft JSON bytes** as the default invocation,
then exits **1** iff `counts.unsupported` is nonzero; otherwise it exits **0**.
The example exits 1 with zero drafts and one unsupported finding. Supported-only,
mixed and all-unsupported inputs all retain their full report, raw source digest,
original pointers and warnings in either mode. The count measures findings: an
unsupported section counts once even if it is empty or contains several entries.
It does not measure drafts, native entries or unresolved review fields.

The gate is evaluated only after full input validation, complete selected-format
write and explicit stdout flush. In Markdown the report and lossless appendix are
fully written before the same unsupported-count gate; unresolved required fields
do not change that count. Invalid syntax/JSON, byte/record/expansion limits and
nonregular/unreadable paths still fail with redacted exit 2 and **empty stdout**,
even if an earlier native entry would have produced an unsupported finding.
Unknown arguments and invalid `--format` values remain redacted
`E_ARGUMENT`/exit 2 with empty stdout. Output write/flush failures
take precedence over the gate and retain Python stream-error behavior; they can
leave partial output and do not promise the input-error status or diagnostics.
`--fail-on-unsupported` is a CLI option; pure import APIs are unchanged.

**Exit 0 is not approval.** Every supported draft still needs human review, with
null owner/status and no automatic actions; even an empty vulnerability section
can exit 0. A partial import must not replace the original ignore file.
Repeated native entries/PURLs are
retained for review; compiling overlapping reviewed records fails `E_CONFLICT`.
Explicit finalization below can exclude a repeated supported draft with a reason.

Accepted syntax is either strict UTF-8 **JSON flow-style YAML** (including this
tool's Trivy output), or this restricted block profile:

- Unquoted section names at column 0; records begin `  - key: value`; remaining
  fields use four spaces; block string-list items use six spaces and `- `.
- Single-line JSON double-quoted strings, YAML single-quoted strings (`''` escapes
  an apostrophe), unambiguous plain strings, and plain `YYYY-MM-DD` dates.
  Inline arrays must use JSON syntax. Empty lists are `[]`.
- Full-line comments and blank lines are allowed; LF and CRLF are accepted.

Other indentation, inline comments, multiline/flow YAML beyond strict JSON,
anchors, aliases, tags, merges, implicit booleans/numbers, directives and multiple
documents are rejected. Duplicate keys, invalid document shapes, invalid UTF-8,
inputs over 2 MiB, more than 10,000 native records or more than 10,000 expanded
drafts fail with **exit 2**, redacted `E_IMPORT` diagnostics and empty stdout.
Unreadable files fail `E_IO`. General YAML normalization must happen externally;
unsupported syntax is never guessed or silently discarded.

## Finalize an explicit native-import review

`finalize-import` validates a completed review against an **unmodified import
draft and the original native bytes**, then prints a normalized v1 decision
document to stdout. It creates no files and performs no scanner or network calls.
The synthetic example uses [`review.json`](../examples/triage/import-trivy/review.json),
which supplies owners and explicit `accepted_risk` decisions for all three drafts:

```sh
vulnwrench triage import-trivy examples/triage/import-trivy/supported.trivyignore.yaml > draft.json
vulnwrench triage finalize-import draft.json \
  --source examples/triage/import-trivy/supported.trivyignore.yaml \
  --review examples/triage/import-trivy/review.json --as-of 2026-11-11 > finalized.json
vulnwrench triage compile finalized.json \
  --as-of 2026-11-11 --author 'Synthetic Example Team' \
  --product-id urn:example:demo-product:1.0 \
  --timestamp 2026-11-11T12:00:00Z --allow-scope-loss --out-dir finalized-out
```

Shell redirections above create the two JSON files; the finalizer writes only
stdout. Success exits 0. Its exact output is saved in
[`expected-finalized.json`](../examples/triage/import-trivy/expected-finalized.json): three
decisions, each with two provenance references; compiling it preserves those
references in the conversion report and emits no OpenVEX for accepted risk.

The review is a strict v1 JSON object with exactly four fields. The legacy form
approves every draft. For a one-record draft, a complete synthetic review has this
shape:

```json
{
  "schemaVersion": 1,
  "decisionDocument": {
    "schemaVersion": 1,
    "decisions": [{
      "ids": ["CVE-2099-0062"], "package": "pkg:npm/triage-demo@1.0",
      "owner": "Synthetic Review Team", "reason": "Synthetic assessment",
      "expiresOn": "2026-12-01", "status": "accepted_risk"
    }]
  },
  "approvedDecisionIndices": [0],
  "unsupportedDispositions": []
}
```

Use the linked three-record fixture for the command above. Keep record count and
order identical to the original draft. For approved rows, fill **every** missing
field, choose an exact versioned PURL for all-package drafts, and explicitly supply
status evidence
where required. Non-null native IDs, exact PURLs, reasons and expiry dates must
remain unchanged. Optional aliases, `decisionId`, `sourceRefs` and status evidence
are explicit reviewer input; no stable identity or security assertion is inferred.
`approvedDecisionIndices` must contain every zero-based draft index exactly once;
this acknowledges review of each record, including package-scope narrowing.

To exclude supported drafts, replace `approvedDecisionIndices` with
`decisionDispositions`. Supply **exactly one** object for every original draft
index. For two repeated native entries, exclude the first and approve the second:

```json
"decisionDispositions": [
  {"decisionIndex": 0, "disposition": "exclude", "reason": "Repeated entry; approve draft 1 instead."},
  {"decisionIndex": 1, "disposition": "approve"}
]
```

This fragment replaces one field in the complete review object above. Keep the
full `decisionDocument.decisions` array in original order. An **excluded slot must
remain exactly the original draft row**, including unresolved null fields; do not
complete or remove it. An approved slot must be completed as described above.
Approval objects have only `decisionIndex` and `disposition`; exclusion objects
also require `reason`, using the same nonempty text profile as decision reasons.
Indices must be integers, excluding booleans, and within the original draft range.
Missing, duplicate, conflicting, extra or unknown indices/dispositions/fields fail
`E_FINALIZE`, as do both approval formats together, neither format, reasons on
approvals or missing/invalid exclusion reasons. Disposition array order does not
control output order.

Only explicitly approved rows are validated together for policy/evidence,
identity/alias overlap and expiry, then emitted in original draft order. This
allows a reviewer to resolve repeated supported entries without changing native
bytes or the verified import report. Approving both duplicates still fails
`E_CONFLICT`; excluding every draft fails `E_INPUT` because output must be nonempty.
Unsupported findings still need their own dispositions below. Excluding a draft
does not discharge those findings or authorize unsupported scope.

Every `unsupported` finding must have exactly one disposition, matched by its
escaped JSON pointer. Only **exclusion** is supported; for example, a blocked
path selector at `/vulnerabilities/1/paths` requires:

```json
{"pointer": "/vulnerabilities/1/paths", "disposition": "exclude", "reason": "Keep this rule in the original configuration for separate review."}
```

Place that object in `unsupportedDispositions`. Reasons use the same nonempty
text profile as decision reasons. Missing, duplicate, extra or unknown dispositions
fail; `accept` cannot turn an unsupported selector into a broader suppression.
An empty disposition array is required when there are no findings. An all-unsupported
input cannot produce a valid decision document. Exclusion means the resulting
document covers only the approved supported entries; retain the original file and review
record, and do not treat a partial import as a complete replacement.

The finalizer regenerates the entire draft from `--source`, checking all metadata
and the byte digest, including comments/whitespace. It applies strict decision
validation to approved rows, overlap checks and `expiresOn > --as-of` before
emitting anything. Invalid review fields/versions, changed native policy,
mismatched source/draft, missing approve/exclude dispositions, changed excluded
slots and unsupported disposition errors fail `E_FINALIZE`. Invalid completed
documents/decisions retain the model's `E_INPUT`, `E_PURL`, `E_STATUS`, `E_CONFLICT` or
`E_DATE`; expired decisions fail `E_EXPIRED`. Invalid JSON/encoding or JSON inputs
over 2 MiB fail `E_INPUT`; unreadable or nonregular files fail `E_IO`; unsupported native syntax
fails `E_IMPORT`. All CLI failures exit 2 with empty stdout and redacted diagnostics.
The final document must contain 1–10,000 decisions; each CLI JSON input and native
source remains bounded to 2 MiB.

All three CLI inputs (`DRAFT`, `--source`, `--review`) must resolve to **readable
regular files**. Each reuses the existing `O_NONBLOCK` open and opened-descriptor
regular-type check before reading at most 2 MiB + 1 bytes, closing on success or
refusal. Final and ancestor symlinks to readable regular files remain supported.
FIFOs (with or without a held peer), links to FIFOs, directories, sockets, devices
and missing, dangling or unreadable paths fail promptly with redacted `E_IO`,
exit 2, empty stdout and no files. Regular-input output bytes are unchanged.

Validation order is argument structure, draft read/JSON decode, native source
read, review read/JSON decode, then pure finalization validation and stdout.
Native syntax, source size/digest and semantic draft/review/date checks run only
after both JSON inputs decode. Thus invalid draft JSON precedes a bad source,
a source I/O failure precedes invalid review JSON, and invalid review JSON
precedes malformed native syntax or mismatched draft semantics. Oversized native
source retains `E_IMPORT`; oversized draft/review JSON retains `E_INPUT`.
Default library loaders and pure `finalize_import` behavior are unchanged.
This is trusted-local Linux/POSIX I/O: nonblocking open avoids FIFO rendezvous,
without imposing a filesystem latency deadline, atomic snapshot or defense
against concurrent writers. Reads may update access times.

Supplied `sourceRefs` are preserved in order, then these references are appended
without duplication for each record (shown with placeholders):

- `urn:triage-bridge:trivy-ignore:sha256:RAW_SHA#/vulnerabilities/NATIVE_INDEX`
- `urn:triage-bridge:import-review:sha256:REVIEW_SHA#/decisionDocument/decisions/DRAFT_INDEX`

`RAW_SHA` hashes native bytes. `REVIEW_SHA` hashes the complete supplied review
using the canonical JSON serialization described below, binding approvals,
exclusion reasons and completed fields. After filtering, these pointers still use
the original native and review positions: keeping only draft 1 references
`/decisionDocument/decisions/1`, even though it is output decision 0. Multiple
PURLs can share a native pointer while retaining distinct draft pointers. Keep
those local inputs to resolve the references; the tool does not fetch or store them. Digests identify content and
verify that the supplied draft matches those bytes; they do not authenticate a
reviewer or prove security assertions. Finalization does not authorize OSV scope
loss, issue scanner/VEX files, or withdraw existing artifacts. Compilation
rechecks policy and projection constraints at its own explicit date.

## Supported input: decision document v1

UTF-8 JSON, at most 2 MiB, containing 1–10,000 decisions. `schemaVersion` is
optional and defaults to integer `1`; no other version is supported. Duplicate
JSON keys, non-finite numbers and unknown root/record fields are errors, including
unknown evidence fields. No unknown data is silently dropped.

```json
{
  "schemaVersion": 1,
  "decisions": [
    {
      "ids": ["CVE-2025-0001"],
      "aliases": {"CVE-2025-0001": ["GHSA-demo-0001-0001"]},
      "package": "pkg:npm/demo@1.0",
      "owner": "app-team",
      "reason": "Investigation",
      "expiresOn": "2026-12-01",
      "status": "under_investigation"
    }
  ]
}
```

[`schemas/decisions-v1.schema.json`](triage/schemas/decisions-v1.schema.json) describes the
structural shape; the runtime additionally enforces relational and projection
constraints:

| Field | Meaning and validation |
| --- | --- |
| `decisionId` | Optional for compilation; required for renewal preview. Unique stable decision identity, using the same syntax as a vulnerability ID. Preserve it across owner/scope changes. Retained in conversion reports, not native scanner/VEX fields. |
| `sourceRefs` | Optional unique array of nonempty reference strings, each using the text validation below. Preserved verbatim in order in reports/previews; not interpreted or fetched. Empty arrays normalize to omission. |
| `ids` | Required nonempty, unique list of **independent primary vulnerability IDs** sharing this decision. Each produces its own VEX statement. Syntax: ASCII alphanumeric first, then alphanumeric or `._:+-`, at most 256 characters. |
| `aliases` | Optional object from a primary ID in this record to a unique list of its equivalent IDs. Only these supplied lists expand scanner entries. No lookup, guessed aliases, or transitive expansion. An identifier cannot be assigned to different primaries anywhere in the document. |
| `package` | Required exact **versioned** PURL. Supported generic profile: `pkg:type/[namespace/]name@version[?key=value&...]`; lowercase type and unique sorted lowercase qualifier keys; ASCII serialized segments with uppercase percent escapes and valid UTF-8 decoding. No subpaths, wildcards, empty/dot segments, decoded slashes, whitespace or control characters. No ecosystem-specific name normalization/validation is attempted. |
| `owner`, `reason` | Required nonempty strings with no leading/trailing whitespace, at most 16,384 characters. Quotes, Unicode, internal LF and TAB are preserved and escaped. Other C0 controls, DEL and unpaired surrogates are rejected. |
| `expiresOn` | Required calendar date `YYYY-MM-DD`, interpreted conservatively as the **first invalid UTC day**. Reject when `expiresOn <= --as-of`. |
| `status` | Exactly `accepted_risk`, `not_affected`, `affected`, `fixed`, or `under_investigation`. |
| `justification` | Only for `not_affected`, one of the five official labels below. |
| `impact_statement` | Nonempty text explaining `not_affected`; only allowed for that status. At least this or `justification` is required. |
| `action_statement` | Required nonempty remediation/mitigation statement for `affected`; only allowed for that status. |

Allowed justifications: `component_not_present`, `vulnerable_code_not_present`,
`vulnerable_code_not_in_execute_path`,
`vulnerable_code_cannot_be_controlled_by_adversary`,
`inline_mitigations_already_exist`. The tool checks the label and required text,
not whether the underlying security assessment is true.

Overlapping ID/alias + exact PURL decisions are rejected, including identical
duplicates. Different packages may share IDs. Their OSV global entries may merge
only when reason and expiry are identical; otherwise compilation fails rather
than picking one policy silently.

`--as-of`, `--author`, `--product-id`, and `--timestamp` are mandatory, even for an
accepted-risk-only input. Author is an individual or organization; product ID
must be an absolute IRI. Timestamp accepts RFC3339 seconds, optional up to six
fractional digits and an explicit `Z`/offset, canonicalized to UTC. Its UTC date
must equal `--as-of`, preventing a snapshot from checking a different day's
expiry. No wall-clock defaults, leap seconds, inferred product membership or
inferred author identities are used.

## Mappings and losses

| Artifact | Projection and limits |
| --- | --- |
| `.trivyignore.yaml` | `vulnerabilities[]`: each primary/explicit alias becomes `id`, exact package becomes one-element `purls`, reason becomes `statement`, expiry becomes `expired_at`. It is **JSON flow-style YAML**, a valid YAML 1.1/1.2 representation that needs no YAML dependency. Only vulnerability ignores are supported. Trivy's documented YAML feature is experimental and must be selected with its ignorefile option. |
| `osv-scanner.toml` | One `[[IgnoredVulns]]` per projected ID, with `id`, exact `reason`, and a native TOML local-date `effectiveUntil`. No `PackageOverrides` approximation. OSV config placement/override options determine its runtime scope; ID ignores cannot encode our exact package constraint. OSV can also expand aliases using its own database, beyond the IDs supplied here. |
| `openvex.json` | Only explicit VEX statuses. The supplied product IRI is `products[].@id`; the exact package PURL is a subcomponent `@id`. Primary ID becomes `vulnerability.name`, supplied aliases become `vulnerability.aliases`. Justification/impact/action map directly. Reason, owner and exception expiry are preserved as informational `status_notes`. |
| `conversion-report.json` | Versioned JSON: normalized source records and indices, input-content digest, parameters, expanded ID mappings, output hashes, counts, omissions and structured per-target losses. Scanner formats do not carry structured ownership, VEX status or VEX explanations. |

**OpenVEX has no native expiry.** Notes do not make consumers stop trusting a
statement on expiry. Regenerate and withdraw stale VEX documents through your
own process. Native scanner expiry handling also belongs to each consumer;
`vulnwrench triage` checks the conservative UTC boundary at compile time, not on every
later use of these static artifacts.

If every decision is `accepted_risk`, `openvex.json` is omitted and the report
explains why. An empty statements array would violate the checked-in official
schema. Mixed documents omit only the accepted-risk statements, never silently.

All artifacts are deterministic for fixed input and parameters. OpenVEX IDs are
`urn:sha256:` plus the SHA-256 of the document without `@id`; each changed document
gets its own ID and version 1. Hash serialization is UTF-8 JSON, sorted object
keys, two-space indentation, unescaped Unicode and one trailing LF (not RFC 8785
JCS). The input digest uses the same serialization of the decoded source object.
Hashes provide reproducibility, not signatures or authenticated provenance.

## Library

```python
from vulnwrench.triage import compile_decisions, load_document, write_compilation

result = compile_decisions(
    load_document("examples/triage/decisions.json"),
    as_of="2026-11-11", author="Synthetic Example Team",
    product_id="urn:example:demo-product:1.0", timestamp="2026-11-11T12:00:00Z",
    allow_scope_loss=True,
)
assert result.report["counts"]["vexStatements"] == 1
# result.files is a read-only mapping of filenames to UTF-8 bytes.
# write_compilation(result, "new-output-directory")
```

`parse_decisions()` also exposes frozen `Decision`/`Vulnerability` models.
`compile_decisions()` performs no I/O; `load_document()` and
`write_compilation()` are explicit I/O helpers. Errors are `BridgeError` with a
stable `.code` and diagnostics that do not echo input values or paths.

`preview_renewal(prior, prior_as_of="2026-11-01", as_of="2026-11-11",
current=candidate, expiring_within_days=7)` returns the JSON-compatible review-plan
dict without I/O. Omit `current` for date-only review; explicitly passing `None`
is invalid. It shares the strict decision validator, allowing missing owners only
for review. The compiler always applies the strict owner and expiry checks again.
For a saved report use `preview_renewal(report, prior_format="conversion-report",
as_of="2026-11-11", current=candidate)`; `prior_as_of` defaults to the archived
`parameters.asOf` and, if supplied, must match it. Report validation and review
perform no I/O. Report records must satisfy strict compilation validation at the
archived date. `verify_report_artifacts(report, directory)` is a separate explicit-I/O
helper: it first validates the report, then returns the `artifactVerification` result
described above. The CLI attaches that result only when `--verify-artifacts` is used.

`import_trivy_ignore(raw_bytes)` returns the review-only native import report
without I/O; `load_trivy_ignore(path, regular_only=False)` is its bounded
file-reading helper. Explicit `regular_only=True` uses the import CLI's
nonblocking-open/regular-descriptor policy while retaining regular-file symlinks.
Native import returns a report with incomplete decision drafts, not a `Compilation`.

`finalize_import(draft, source=raw_bytes, review=completed_review,
as_of="2026-11-11")` returns a normalized v1 decision document with source
references. It performs no I/O and does not mutate either supplied object.

CLI exit codes: **0** success/help/version; **2** invalid/unsupported input,
expired policy, unapproved scope loss, contradictory projection, or I/O error.
With `preview-renewal --fail-on-review`, **1** means a successfully printed review
plan has a nonzero `counts.reviewRequired`; a zero count exits 0. Without the flag,
valid previews always exit 0. With `import-trivy --fail-on-unsupported`, **1** means
a successfully written/flushed draft has nonzero `counts.unsupported`; default
valid imports exit 0. Neither import status approves any draft. Output-stream
failures retain Python behavior and take precedence over these gates.
The example verifier also uses exit 1 if its own
checks fail. On compilation failure no new output is intentionally retained.
Unknown options/subcommands are also redacted; no traceback or input excerpt is
printed for documented failures.

## Upstreams, alternatives and boundaries

[Trivy](https://github.com/aquasecurity/trivy) and
[OSV-Scanner](https://github.com/google/osv-scanner) already support expiring
ignores; [vexctl](https://github.com/openvex/vexctl) already creates and merges
VEX. This tool adds a deliberately small central decision schema, explicit
package-scope loss authorization and traceable projections. It does not replace
those scanners, invent VEX, or claim that existing tools cannot track expiry.

Field mappings follow the official documentation:
[Trivy filtering](https://trivy.dev/latest/docs/configuration/filtering/),
[OSV-Scanner configuration](https://google.github.io/osv-scanner/configuration/),
the [OpenVEX v0.2 specification](https://github.com/openvex/spec), and the
[official OpenVEX schema](triage/schemas/openvex-v0.2.0.schema.json) (CC0-1.0, redistributed unmodified).
No network access or scanner execution is required.

Supported scope is strict decision JSON **compile input**, the three documented
output formats, validated conversion-report baselines with optional original-source
and saved-byte verification, a renewal
review plan, and review-only import
of the specified Trivy ignore YAML subset. It does not import scanner reports,
other native configurations, Grype YAML, arbitrary YAML/TOML, SBOMs or existing
VEX. Unsupported selectors are reported; unsupported syntax fails.
No network, scanner execution, target code, lifecycle scripts, API keys, signing,
auto-upload, persistent service, exploitability inference or production
configuration update is involved. Consumer binaries were not executed: these
checks establish documented-format/field compatibility, not certification for
every scanner release. The writer targets Linux/POSIX filesystem semantics.
