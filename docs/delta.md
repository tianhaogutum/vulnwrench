# vulnwrench delta

A rebuilt image or a lockfile bump changes the scanner report, but a raw diff of two reports
cannot tell a real fix from a renamed advisory, a removed package, a changed vulnerability
database or a package the scanner simply stopped seeing. `vulnwrench delta` compares two Trivy
(or pinned Grype 0.86.1) reports against the CycloneDX inventories they were run on and
classifies every finding as introduced, persistent, fixed, removed or still affected after a
version change, keeping the evidence for each decision. Use it in CI to gate on newly
introduced findings, or to answer "did this upgrade actually fix CVE-X?".

_Formerly the standalone `scan-delta` tool._

It joins explicit advisory aliases, keeps package copies separate, and distinguishes a missing
finding from a package removal or a fix supported within one advisory snapshot. It never invokes
a scanner, executes target code, installs target packages, edits lockfiles, or uses the network.
Standard library only.

## Quick start

From a clone of the repository (the inputs are synthetic fixtures under
[`examples/delta/`](../examples/delta/)):

```sh
vulnwrench delta compare \
  --before examples/delta/before.json --after examples/delta/after.json \
  --before-bom examples/delta/before-bom.json --after-bom examples/delta/after-bom.json \
  --metadata examples/delta/scans.json --output out.json
```

Markdown and the policy gate use the same inputs:

```sh
vulnwrench delta compare \
  --before examples/delta/before.json --after examples/delta/after.json \
  --before-bom examples/delta/before-bom.json --after-bom examples/delta/after-bom.json \
  --metadata examples/delta/scans.json --format markdown --output out.md

vulnwrench delta compare \
  --before examples/delta/before.json --after examples/delta/after.json \
  --before-bom examples/delta/before-bom.json --after-bom examples/delta/after-bom.json \
  --metadata examples/delta/scans.json --fail-on introduced --output out.json
```

The last command intentionally exits **1** for this fixture, after writing the
matrix. Exit **0** means successful processing / passing gate; **2** means
invalid or unsupported input, missing arguments or an I/O error. The opt-in
[`--fail-on-unknown` gate](#opt-in-unknown-evidence-gate) exits **3** after writing
unknown or incomparable evidence. `--output`
defaults to stdout. A file output is replaced atomically only after successful
validation; output cannot overwrite any input (including hardlinks/symlinks).
The output parent directory must already exist.

To trace one advisory through the same decisions, use `explain`
([details below](#explain-one-advisorys-findings)):

```sh
vulnwrench delta explain --advisory GHSA-SYNTH-001 \
  --before examples/delta/grype/trivy-before.json --after examples/delta/grype/trivy-after.json \
  --before-bom examples/delta/grype/before-bom.json --after-bom examples/delta/grype/after-bom.json \
  --metadata examples/delta/grype/trivy-scans.json
```

```json
{
```

## Exact supported input contract

All five inputs are required local UTF-8 JSON files, at most **20 MiB each**.
Duplicate JSON object keys, non-finite numbers and malformed encodings are
rejected. This is a supported subset parser, not a complete official schema
validator. Unsupported known semantic structures fail with exit 2; unknown
extension fields are retained verbatim in evidence and **are not interpreted**.

### Trivy reports

Trivy sides must use native JSON `SchemaVersion: 2` and a `Results` array.
OSV, SARIF, XML and other Trivy schema versions are unsupported. Each side's
manifest scanner selects its parser; mixed Trivy/Grype observations can match,
but scanner identity changes always prevent a fix claim.
Trivy's schema version does not guarantee all reports fit this
subset; the `0.58.0` value in the sample metadata is a synthetic identity, not
an assertion that every output from that release is supported.

Every result needs a nonempty `Target`, `Class: "lang-pkgs"`, and either
`Type: "node-pkg"` (npm) or `Type: "python-pkg"` (PyPI). Target/type pairs
must be unique. Empty `Results` is valid but missing target coverage makes
snapshots incomparable. `Vulnerabilities` may be absent, null or an array.
Nonempty secrets, misconfigurations, licenses, custom resources, modified
findings and explicit scan errors are rejected. OS package / container-layer
results are unsupported even when their findings array is empty.

Each vulnerability requires:

| Trivy field | Mapping |
| --- | --- |
| `VulnerabilityID` | Literal advisory ID; only explicit manifest aliases can join it |
| `PkgIdentifier.PURL` | Versioned `pkg:npm/...@version` or `pkg:pypi/...@version` identity |
| `PkgName` | Must agree with decoded PURL name, after PyPI normalization |
| `InstalledVersion` | Must agree exactly with decoded PURL version |
| `PkgPath` | Optional string; absent/empty means empty package path |
| result `Target` | Exact scan scope (typically a lockfile or environment path) |

No fallback from a missing PURL, path guessing, URL-to-alias inference or
semantic version ordering occurs. npm scoped names (`@team/demo`) and PURL
percent encoding are supported; PyPI names lowercase and normalize runs of
`-_.` to `-`. PURL qualifiers are decoded and sorted, then retained as part
of package identity. Duplicate qualifiers and PURL subpaths (`#...`) are
unsupported. Names follow the conservative ASCII npm/PyPI syntax enforced by
the parser. Package versions are strings compared for equality.

### Grype JSON adapter v1 (0.86.1 only)

The independent adapter is pinned to Grype **0.86.1**, not to an assumed stable
JSON schema. Both `descriptor.name/version` and the manifest scanner must say
`grype` / `0.86.1`. The format references are the pinned upstream
[document](https://github.com/anchore/grype/blob/v0.86.1/grype/presenter/models/document.go),
[match](https://github.com/anchore/grype/blob/v0.86.1/grype/presenter/models/match.go),
[package](https://github.com/anchore/grype/blob/v0.86.1/grype/presenter/models/package.go),
[source](https://github.com/anchore/grype/blob/v0.86.1/grype/presenter/models/source.go)
models, the native
[DB status](https://github.com/anchore/grype/blob/v0.86.1/grype/db/legacy/distribution/status.go),
and Syft 1.18.1's
[file coordinates](https://github.com/anchore/syft/blob/v1.18.1/syft/file/coordinates.go).
These are format references; no upstream implementation is copied or run.
The paired synthetic Trivy fixtures follow the
[0.58.0 report model](https://github.com/aquasecurity/trivy/blob/v0.58.0/pkg/types/report.go).

Only `source.type: "directory"` or `"file"` with a nonempty string target is
accepted. `matches` must be an array. Each match requires `vulnerability.id`
and an artifact with `id`, `name`, `version`, `type`, and `locations`.
Supported artifact types are `npm` and `python` (PyPI); versioned PURLs and
name/version agreement use the same normalization as Trivy. Report-local
artifact IDs are never compared across scans. `relatedVulnerabilities`,
advisory URLs, matcher details and `fix.versions/state` are retained evidence;
they do not infer aliases, ordering, or remediation.

Grype locations do not identify the Trivy-style target and package-copy scope.
Each Grype side therefore requires an additional manifest field, for example:

```json
"grype": {
  "adapter_version": 1,
  "targets": [{"target": "package-lock.json", "type": "node-pkg"}],
  "bindings": [{
    "artifact_id": "synthetic-demo-1.0",
    "target": "package-lock.json",
    "package_path": "node_modules/demo",
    "location": {"path": "/workspace/node_modules/demo/package.json"}
  }]
}
```

Supply these bindings from authorized inventory knowledge. `targets` explicitly
attests to target/type coverage even when there are no matches, using the same
`node-pkg` / `python-pkg` labels as Trivy. Bindings require a unique artifact ID,
a declared target, a literal package path (which may be empty), and an exact
native location object. A match needs exactly one native location and its
binding must equal that coordinate, including any `layerID` field. Nonempty
layer IDs are unsupported. No path stripping, directory inference, layer
flattening, or automatic mapping to a BOM occurs. The mapped scope must still
agree with the separately supplied CycloneDX inventory.

An absent binding, zero/multiple locations, conflicting reuse of an artifact
ID, unsupported package/PURL, or inconsistent identity yields an
`unknown_findings` entry with reasons and the original match pointer. Such
entries cannot safely be assigned a package scope. They make the comparison
incomparable (`report_identity_unknown`) and conservatively block **all** fix
and removal claims, while known positive observations still compare.
Every match is accounted for exactly once, in a transition or an unknown entry.
`adapter_provenance` links normalized matches to native location and manifest
binding pointers. All original report/manifest fields remain in evidence.

Malformed required structures, unsupported adapter/scanner versions, image or
unknown source types, explicit errors, nonempty `ignoredMatches`, duplicate
bindings, and undeclared binding targets fail with `InputError` / CLI exit 2.
Grype DB timestamps, schema versions and download locations never supply a
snapshot identity: the manifest's complete database content identity and
profile/completeness attestations remain required. Native DB metadata is
retained and a nonempty `descriptor.db.error` is rejected. Conflicting native
DB checksums/schema versions or differing exported configurations also prevent
a fix claim even when the manifest identities agree. Native equality or absent
native metadata never substitutes for the manifest's full snapshot/profile
identity. Configuration comparison is deliberately conservative: even a change
to an irrelevant exported setting prevents a fix label. These checks do not
authenticate the caller's attestations.

Run the pinned synthetic example:

```sh
vulnwrench delta compare \
  --before examples/delta/grype/before.json --after examples/delta/grype/after.json \
  --before-bom examples/delta/grype/before-bom.json --after-bom examples/delta/grype/after-bom.json \
  --metadata examples/delta/grype/scans.json
python scripts/delta/verify_grype.py
```

Expected: one `version_changed_still_affected` row, canonical advisory
`CVE-SYNTH-001`, versions `1.0` → `1.1`, path `node_modules/demo`, `fixed: false`.
The matching `trivy-*.json` fixtures yield identical semantic rows under their
own scanner profile. This does not assert that actual Trivy and Grype
databases or profiles are interchangeable. A changed database/profile produces
incomparability; a second native location produces an unknown after finding
and `no_longer_reported` for the prior row, never a fix.

### CycloneDX inventories

Both BOMs must have `bomFormat: "CycloneDX"`, `specVersion` equal to `1.4`,
`1.5`, or `1.6`, and an explicit `components` array (which may be empty).
Components, including nested `components`, must have `type: "library"`, a
unique nonempty `bom-ref`, `name`, `version`, and a versioned npm/PyPI `purl`.
`name` and optional `group` must agree with the PURL; scoped npm can use
`group: "@team", name: "demo"` or a full scoped name without a group.
Metadata root applications and dependency graphs are retained but not used as
package inventory. Non-library entries in `components` are rejected.

Each component requires a standard CycloneDX `properties` entry tying it to
the exact report target. A nonempty Trivy `PkgPath` requires its exact matching
package-path property too:

```json
{
  "type": "library",
  "bom-ref": "demo-at-lockfile",
  "name": "demo",
  "version": "1.1",
  "purl": "pkg:npm/demo@1.1",
  "properties": [
    {"name": "scan-delta:target", "value": "package-lock.json"},
    {"name": "scan-delta:package-path", "value": "node_modules/demo"}
  ]
}
```

These `scan-delta:*` properties (the name is kept from the original tool so existing
inventories keep working) are this tool's explicit scope convention, not
native scanner claims. Supply them from authorized inventory knowledge; this
tool does not discover or generate them. Other properties are retained.
Unknown or duplicate `scan-delta:*` properties fail. Paths and targets are
literal strings (no filesystem resolution or case folding). The key is
`(ecosystem, name, target, package path, qualifiers)`; versions remain attached
to observations. Different copies never merge. Duplicate inventory keys with
the same version fail instead of silently collapsing; multiple versions per
scope are allowed and compared as version sets.

### Metadata manifest

[examples/delta/scans.json](../examples/delta/scans.json) shows the complete schema:

```json
{
  "schema_version": 1,
  "before": {
    "scanner": {"name": "trivy", "version": "0.58.0"},
    "database": {"id": "sha256:synthetic-db-A"},
    "profile": "synthetic-npm-full-unfiltered-v1",
    "report_complete": true,
    "inventory_complete": true
  },
  "after": {
    "scanner": {"name": "trivy", "version": "0.58.0"},
    "database": {"id": "sha256:synthetic-db-A"},
    "profile": "synthetic-npm-full-unfiltered-v1",
    "report_complete": true,
    "inventory_complete": true
  },
  "aliases": {"GHSA-SYNTH-DEMO": ["CVE-SYNTH-DEMO"]}
}
```

Manifest fields are strict: unknown fields fail. The `grype` side field above
is required only for Grype; Trivy sides retain the original schema. `aliases` is optional; values
are arrays of explicit equivalent IDs. Equivalence is transitive, cycles are
safe, and the lexicographically smallest ID is canonical. No online lookup or
heuristic alias discovery is performed.

`database` is required but may be `{}` or `{"id": null}` when identity is
unknown: this gives `database_identity_missing`, never an invented identity.
Use a stable content identity for the **entire advisory snapshot**, including
all advisory databases relevant to the scan; a schema version, download time
alone, or mutable tag is insufficient. `profile` is a caller-chosen stable
identity of scanner settings: vulnerability checks, analyzers, filters,
ignore/VEX settings, scope and other coverage-affecting configuration.
`report_complete: true` attests to complete, successful, unfiltered exports;
`inventory_complete: true` attests to complete scoped package inventory.
False flags are allowed and prevent a fix claim.

These are caller attestations: the tool cannot authenticate that the metadata
is truthful or that reports and inventories describe the same artifact. Use
consistent, authorized inputs. Source digests provide reproducibility, not
authenticity. An invalid or unavailable inventory file is an error; an empty
or partial inventory is explicit evidence, not proof of removal by itself.

## Classification rules and output

| Classification | Evidence / meaning |
| --- | --- |
| `introduced` | Advisory equivalence class newly observed for this package scope; not proof it was newly introduced in code |
| `persistent` | Both reports observe it with identical version sets |
| `version_changed_still_affected` | Both observe it, but version sets differ |
| `package_removed` | Previously inventoried finding's whole package scope is absent from a complete after inventory; not a remediation claim |
| `fixed_within_snapshot` | Prior finding absent, package scope still inventoried, and all fix preconditions below hold |
| `no_longer_reported` | Absence cannot establish removal/fix; `resolution` says `unresolved` or `incomparable` and `reasons` explains why |

A `fixed_within_snapshot` row requires equal scanner name **and version**,
known equal database identities, equal profiles and target/type coverage,
both reports and inventories attested complete, the prior finding exactly
inventoried, and the same package scope still present after (possibly at a
new version). Only that class has `fixed: true`. Disappeared findings whose
inventory match is missing remain unresolved. Complete inventory can support
`package_removed` even with different databases; that row still has
`fixed: false`. An unrelated missing target conservatively prevents fix labels
across the comparison.

Inventory consistency is checked across **all advisories in each package
scope**. If the after report observes advisory B for a package omitted from
the after BOM, disappearing advisory A is `no_longer_reported` with
`report_inventory_conflict`, never `package_removed`. A stale BOM version
also prevents a fix claim in that scope. Different targets, paths and
qualifiers remain separate scopes.

Global `comparable` describes metadata/coverage comparability; a row may
add `finding_missing_from_inventory` even when global comparability is true.
Persistent observations can still be matched across different snapshots,
with incomparability reasons retained. `--fail-on introduced` gates newly
**observed** findings even if the snapshots are incomparable. There is no
claim that all advisories were found, that disappeared IDs were truly fixed,
or that a version is safe. Undeclared alias changes remain distinct IDs.

### Opt-in unknown-evidence gate

`compare --fail-on-unknown` writes the same complete JSON or Markdown evidence
as an ungated comparison, then exits **3** if **any** of these holds:

- `comparable` is false, including missing/changed database identities,
  scanner/profile/coverage differences or incomplete reports/inventories;
- either side has nonempty Grype `unknown_findings`, even with no normalized rows;
- any transition has nonempty `reasons`, including missing inventory records
  or scope-wide `report_inventory_conflict` while global `comparable` is true.

This is an evidence-quality policy, so persistent findings, known introduced
findings, supported fixes/removals, and comparable empty reports pass when
they have no evidence blockers. Uninterpreted extension fields alone do not
trigger it. A pass does not prove that supplied attestations are truthful or
that all vulnerabilities were found. No classifications or result fields change.

```sh
vulnwrench delta compare \
  --before examples/delta/grype/trivy-before.json --after examples/delta/explain/absent-after.json \
  --before-bom examples/delta/grype/before-bom.json --after-bom examples/delta/grype/after-bom.json \
  --metadata examples/delta/explain/changed-db.json \
  --fail-on-unknown --output uncertain.json
```

This synthetic example writes `no_longer_reported`, `fixed: false`,
`comparable: false` and `database_identity_changed`, then exits **3**.
Without this flag it writes identical evidence and exits **0**.

Both gates may be combined: `--fail-on introduced --fail-on-unknown`.
Exit **3** takes precedence over **1** when both fail; **1** means only the
introduced policy failed. Validation or I/O errors remain exit **2** and take
precedence over policy evaluation. Invalid inputs preserve an existing output;
a valid policy failure replaces it atomically with the full new evidence.
Stdout also retains complete output on policy failure; gate failures add no
stderr diagnostics. `explain` does not accept either policy flag.

Stdout is flushed before a successful processing or policy exit is returned.
A write or flush error (including a closed pipe or full output device) exits
**2** with a value-redacted diagnostic, overriding **0**, **1** or **3**.
An output error can leave a partial stdout stream; it cannot be rolled back.
Flushing does not guarantee disk durability or acknowledgement by a downstream
consumer. Use `--output FILE` for atomic replacement of a local evidence file.

| Input / policy | Expected exit and output |
| --- | --- |
| Comparable persistent or empty reports, unknown gate | 0, full evidence |
| Comparable introduced row, unknown gate only | 0, full evidence |
| Comparable introduced row, both gates | 1, full evidence |
| Changed/missing database, incomplete input attestations or coverage mismatch, unknown gate | 3, full evidence even with no transitions |
| Grype unknown on either side, unknown gate | 3, retained unknown records and accounting |
| Missing/stale scoped BOM entry, unknown gate | 3, retained row blockers even if globally comparable |
| Introduced row plus evidence blocker, both gates | 3, full evidence |
| Malformed/unsupported input or output write error, either gate | 2; no successful output |
| Stdout write/flush error, including a closed pipe or full device | 2, value-redacted stderr; stdout may be partial |

`--fail-on introduced` alone continues to cover only normalized newly observed
rows. Without `--fail-on-unknown`, inspect comparability, row reasons and unknown
findings explicitly; successful processing can include no normalized rows.

JSON includes deterministic sorted rows, classification counts, original
IDs, all known aliases, versions, reasons, source JSON pointers and record
accounting. Duplicate scan records aggregate without being lost. Inventory
pointers identify supporting components. `evidence` embeds all five original
JSON documents, including unknown extension fields, with SHA-256 of their
canonical JSON (`sort_keys=True`, ASCII escaped, compact separators, UTF-8).
Pointers such as `/before_report/Results/0/Vulnerabilities/0` resolve against
the object formed by each `evidence` entry's `document`. Digests cover parsed
content, not original whitespace or file bytes. Markdown contains the matrix
plus this same full JSON evidence appendix.

**Successful outputs are not redacted**: retained inputs may contain sensitive
paths or other evidence. Use synthetic/authorized sanitized inputs and treat
the output accordingly. Validation and I/O diagnostics omit input values,
filenames and OS exception text; invalid JSON doesn't echo its contents.

Library use takes parsed JSON-compatible objects and returns a JSON-compatible
result without changing the inputs:

```python
from vulnwrench.scandelta import compare, InputError
# result = compare(before, after, before_bom, after_bom, metadata)
# Invalid/unsupported supported-format evidence raises InputError.
```

## Explain one advisory's findings

`explain` uses the same validated inputs and batch decisions as `compare`:

```sh
vulnwrench delta explain --advisory GHSA-SYNTH-001 \
  --before examples/delta/grype/trivy-before.json \
  --after examples/delta/grype/trivy-after.json \
  --before-bom examples/delta/grype/before-bom.json \
  --after-bom examples/delta/grype/after-bom.json \
  --metadata examples/delta/grype/trivy-scans.json
```

This synthetic upgrade returns `version_changed_still_affected`, `fixed: false`,
with `version_sets_changed` and `explicit_alias_equivalence` reasons. The
before/after native finding pointers and the explicit manifest alias entry
support those reasons. `--format markdown` shows reason and prerequisite tables
as well as the full evidence appendix; `--output FILE` uses the same atomic
write and input protection as `compare`.

The JSON is the **complete batch result**, plus an `explanation` object with
`schema_version: 1`, `requested_advisory` and `findings`. Each finding has a
zero-based `transition_index` into the batch matrix, a `decision` copied from
that row (`classification`, `resolution`, `fixed`), machine-readable `reasons`,
and `fix_prerequisites` with `code`, `satisfied` and `sources`. The selector
matches an exact observed ID or any explicitly declared transitive alias.
All matching package scopes are explained separately; duplicate records retain
their pointers. Batch summary, accounting, unknown findings and evidence cover
the entire comparison, including unselected rows.

An exact native advisory ID also selects unknown Grype records. When any are
selected, `explanation.unknown_findings` contains entries with `side`,
`unknown_index` (into the full result's `unknown_findings[side]` array),
`advisory`, the original native match `source`, and `reasons` containing the
adapter's existing `code` values and `sources` starting with that match pointer. Each pointer resolves
against retained evidence. Duplicate native records keep separate entries.
These entries have no normalized package scope, transition, inventory assignment,
decision, `fixed` label or fix prerequisites. Unknown evidence still makes the
batch incomparable and blocks all fix/removal claims. The `findings` array may
be empty; it continues to contain only normalized transition explanations.
Known-only explanation objects retain their existing shape.

Unknown blockers also cite the supporting retained evidence:

| Unknown reason | Additional source pointers |
| --- | --- |
| `artifact_id_conflict` | The native artifact's `id`, then every artifact record sharing that ID within the same report, in original match order (including the selected artifact, duplicates and unselected matches) |
| `ambiguous_package_location` | The native artifact's `locations` array, including when empty |
| `unsupported_package_location` | The native `locations/0` coordinate with the unsupported layer |
| `scope_binding_missing` | The native artifact's `id` and the manifest's `grype/bindings` container |
| `scope_binding_location_mismatch` | The native artifact's `id`, its `locations/0` coordinate and the matching manifest binding's `location` |
| `unsupported_package_type` | The native artifact's `type` |
| `package_identity_unsupported` | The native artifact's `purl` when that key exists; otherwise the artifact container |
| `package_identity_disagrees` | The native artifact's `type`, `name`, `version` and `purl`, in that order |
| `scope_binding_type_mismatch` | The native artifact's `id` and `purl`, the matching manifest binding's `target` at its original array index, and the manifest's `grype/targets` container |

For example, the mixed fixture's missing-binding reason cites
`/after_report/matches/1`, `/after_report/matches/1/artifact/id` and
`/metadata/after/grype/bindings`. The container shows the supplied bindings;
no nonexistent binding entry is referenced. A mismatched binding's location
pointer uses its original manifest array index. A missing PURL cites
`/after_report/matches/0/artifact`, never a nonexistent `/purl` field. A present
but invalid PURL (including null, an empty string or an unsupported ecosystem)
cites the retained field itself. Required `name`, `type`, `version` and
`locations` fields remain validation errors when missing or malformed; they
are not turned into unknown records. Artifact-ID conflict context includes whole retained
artifact records because differences in extension fields also trigger the existing
conservative conflict rule. It never joins IDs across reports or includes artifacts
with a different ID; identical artifacts alone do not create a conflict.
For binding-type mismatches the target/type container shows the declared
coverage, including the absence of a compatible type at the bound target;
a compatible type at a different target does not resolve that mismatch. These pointers explain why a scope could not
be established; they do not assign the unknown record to a package or inventory.

The two artifact-conflict fixtures in the [unknown fixture contract](../examples/delta/explain/unknown-cases.json)
cover an unknown-only before report with differing versions/PURLs and a mixed after
report whose artifacts differ only in retained extension fields. The latter keeps
the known upgrade and cites `/after_report/matches/1/artifact`,
`/after_report/matches/3/artifact` and `/after_report/matches/4/artifact` for each
selected conflict, after its own match and `artifact/id` pointers. Match 1 is
unselected; unrelated match 2 and the before report are excluded from these sources.
Duplicate selected matches retain separate original match and unknown indexes.
For the CLI, use `--before examples/delta/grype/before.json`,
`--after examples/delta/explain/conflict-mixed-after.json`, the Grype BOMs and
`--metadata examples/delta/explain/conflict-scans.json` with `explain --advisory GHSA-SYNTH-001`.
Both JSON and Markdown exit **0**, retain all one before / five after records and
block fix/removal claims. Selecting an alias does not select unknown conflicts;
missing/empty/absent or related/extension-only selectors still exit **2** safely,
preserving existing output. Malformed conflicting or unselected matches remain
validation errors; context generation does not bypass report validation.

An optional normalized-target drilldown uses `explain --advisory ID --target TARGET`.
The library equivalent is `compare(..., explain_advisory=ID, explain_target=TARGET)`.
It selects **whole normalized explanation entries** whose existing transition
`package.target` equals the requested string. Observed IDs and explicitly declared
aliases keep their existing normalized equivalence semantics. Target matching is
exact: no trimming, case folding, path normalization, basename matching or inference
from native artifact locations or inventory. Separate package paths and qualifiers
at that target remain separate entries with their original `transition_index`,
ordered reasons, fix prerequisites, decisions and resolving source pointers.

The opt-in metadata is `explanation.normalized_filter = {"target": TARGET}`;
Markdown adds `Normalized target filter: TARGET` using the existing escaping.
At least one **normalized** entry must match both advisory and target. Unknown-only
advisories cannot satisfy this requirement. Unknown explanation entries are omitted
from this view: unknown native records have no normalized target. Complete unknown
records, native reports, adapter provenance, batch transitions, evidence, accounting
and conservative fix/removal blockers remain unchanged. A blocker from an unselected
target or unknown native record still applies to selected entries.

`--target` requires `--advisory` and is mutually exclusive with every native unknown
selector: `--side`, `--artifact-id`, `--reason-code`, `--reason-code-all`,
`--reason-code-any` and `--match-index` (including index zero). Empty, whitespace-only,
control-character, non-string library, inexact, mismatched and no-match selectors
raise `InputError` / CLI exit **2**. Invalid requests write no stdout and preserve
existing output files; diagnostics omit selector values. All five inputs, including
unselected/opposite-side records and inventory, are fully validated. Omitting the
selector (library `None`) preserves previous compare/explain JSON and Markdown bytes,
including scalar/ALL/ANY unknown drilldowns. Successful target explanations exit **0**.

The [target contract](../examples/delta/explain/target-cases.json) covers Trivy, pinned Grype
and mixed scanners, an explicit transitive alias, multiple targets, two package copies,
unknown blockers and a target with significant spaces and Markdown punctuation:

An optional `--package-path PATH` (library `explain_package_path=PATH`) refines
this normalized target selection. It requires both advisory and target, matches
`package.path` by exact string equality, and adds `package_path` to
`explanation.normalized_filter`, for example `{"target": " apps/~web|lock.json ",
"package_path": " node_modules/~demo|copy "}`. There is no trimming, case folding,
path normalization, prefix matching or inference from a native location or PURL.
Whole entries retain distinct qualifiers, original transition indexes, every
ordered reason, decision, prerequisite and source pointer. At least one normalized
entry must match **all three** selectors. Unknown-only and mismatched selections
fail; complete unknown/native evidence, accounting and conservative blockers remain
in the unfiltered batch. All unselected and opposite-side evidence is validated.

The empty string is an explicit selector, not omission: `--package-path ''` matches
an existing normalized empty path only. Library `None` or omission preserves all
prior default, target and native scalar/ALL/ANY JSON/Markdown bytes. Non-string,
whitespace-only, control-character, missing/incompatible or no-match selectors
raise `InputError` / CLI exit **2**, with value-free diagnostics, no stdout and
unchanged existing output files. Every native unknown selector is incompatible.
Successful selections exit **0**. Markdown adds an escaped
`Normalized package path filter: PATH` caption, displaying an empty path as `""`.

An optional unknown-artifact drilldown uses **both** `--side before|after` and
`--artifact-id ID` with `--advisory ID`. The library equivalents are
`compare(..., explain_advisory=ID, explain_side="after", explain_artifact_id=ID)`.
Selection requires exact native advisory, side and native `artifact.id` equality;
IDs are local to one report and are never joined across scans or inferred from
PURL, path, BOM, aliases, related IDs or extensions. Strings are not trimmed or
case folded. Both fields must be supplied together with an advisory; empty,
whitespace-only, control-character, invalid-side and no-match selectors fail.
The selected side must be a supported pinned Grype report. All five inputs,
including unselected native records, still undergo complete validation.

With this filter, normalized explanations are deliberately suppressed:
`explanation.findings` is `[]`, and `explanation.unknown_filter` records
`{"side": "after", "artifact_id": "native/~shared ID"}`. At least one unknown
entry must match; a normalized-only match fails. Selected unknown entries keep
their original shape, indexes, separate duplicates, reason order and all
same-report conflict context, including unselected advisories. No scope or
decision is assigned. Complete batch decisions, blockers, accounting and native
evidence remain unchanged. Without the filter, JSON and Markdown are unchanged.
Invalid/unsupported/no-match filters exit **2**, emit value-free diagnostics and
preserve existing output; valid filters exit **0** in JSON and Markdown.

Within that drilldown, optional `--reason-code CODE` (library
`explain_reason_code=CODE`) selects **whole unknown explanation entries** whose
adapter `reasons` contain the exact code. It requires all three existing
advisory/side/artifact selectors. Codes are the emitted native adapter codes in
the unknown-reason table above, not normalized decision reasons, aliases, prefixes
or substrings. There is no trimming or case folding. Every selected entry retains
every original reason in order, its original unknown/native indexes, separate
duplicates and all same-report conflict pointers, including peers excluded by
the reason filter. Entries remain unscoped with no decision; `findings` stays
`[]`, and complete batch evidence/accounting and fix/removal blockers are unchanged.

When supplied, the code adds only `reason_code` to `explanation.unknown_filter`,
for example `{"side": "after", "artifact_id": "native/~shared ID",
"reason_code": "ambiguous_package_location"}`. Markdown also shows an
`Unknown reason filter` caption and every retained reason. Omitting the code
(library `None`) preserves all existing JSON/Markdown bytes, including the
side/artifact-only drilldown. Empty, whitespace-only, control-character,
unsupported and no-match codes fail with `InputError` / CLI exit **2**, no stdout,
value-free diagnostics and unchanged existing output. A code present only on a
different artifact, advisory or report side is not a match. All five inputs are
validated, including unselected native records and unsupported reports.

Each still contains `artifact_id_conflict`, `ambiguous_package_location` and

**1, 3, 4, 6, 7, 8**, including the unselected advisory and reason-excluded peers.

To require **ALL** of several exact reasons, repeat `--reason-code-all CODE`
instead of `--reason-code`. Library callers use
`explain_reason_codes_all=["ambiguous_package_location", "scope_binding_missing"]`.
The library accepts a nonempty list or tuple of valid code strings; `None`
omits the selector. Duplicate codes collapse in first-requested order without
changing the input. A singleton collection is valid. The scalar and ALL
selectors are mutually exclusive, even when they request the same code.
Explicit advisory, side and artifact ID are required. Membership uses exact
emitted adapter codes, with no aliases, trimming, case folding or scope inference.

For example, replace the reason flag in the command above with:


This exits **0** and selects unknown indexes **2, 3** (native matches **3, 4**),
retaining all three original reasons and all conflict peers. Requiring
`artifact_id_conflict` and `scope_binding_missing` selects indexes **2, 3, 5, 6, 7**.
Requiring `ambiguous_package_location` and `unsupported_package_type` fails:
each code occurs in the selected artifact's records, but no entry contains both.
Adding `--match-index 4` intersects the ALL selection with that original native
index, selecting unknown index **3**; it never uses an unknown-array position.

`explanation.unknown_filter` adds `reason_codes_all`, an array of unique codes
in request order. Markdown adds `Unknown reason filter (ALL): CODE, CODE`.
Selection retains whole entries, original reason order/context/indexes and
separate duplicate records, including every same-report conflict peer even when
unselected. `findings` remains `[]`; unknown entries acquire no scope or decision.
Full native evidence, accounting and conservative fix/removal blockers remain
unchanged. Omitting ALL selection preserves all previous JSON/Markdown bytes,
including scalar reason and native-index outputs.

Malformed or empty collections, invalid/unsupported/no-match codes, scalar
conflicts, missing/mismatched selectors and index mismatches produce `InputError`
/ CLI exit **2**, with no stdout, value-free diagnostics and unchanged existing
output. Every input, including unselected/opposite-side reports, is validated.
The [ALL-reason contract](../examples/delta/explain/reason-all-cases.json),
`python -m pytest tests/scandelta/test_reason_all.py` and

behavior through the CLI.

To require **ANY** of several exact reasons, repeat `--reason-code-any CODE`.
Library callers use
`explain_reason_codes_any=["ambiguous_package_location", "unsupported_package_type"]`.
It accepts a nonempty list or tuple of supported code strings, deduplicated in
first-requested order without changing the input. `None` omits it; singletons
are valid. Scalar, ALL and ANY selectors are mutually exclusive, even when
identical or an incompatible collection is empty. Explicit exact advisory,
side and artifact ID are required, with no aliases, trimming, case folding or
scope inference.

For example, replace the reason flag in the reason-filter command above with:

```sh
  --reason-code-any ambiguous_package_location --reason-code-any unsupported_package_type
```

This exits **0**, selecting unknown indexes **2, 3, 7** (native matches **3, 4, 8**).
The first two contain the location reason and the last contains the type reason;
no entry contains both. Overlapping reason sets select each whole entry once,
while separate duplicate records remain separate. Adding `--match-index 4`
intersects this selection, retaining only unknown index **3**; index **8** selects
unknown index **7** and index **7** fails. Indexes always refer to the original
native `matches` array, never the unknown array.

`explanation.unknown_filter.reason_codes_any` contains the unique codes in
request order; Markdown adds `Unknown reason filter (ANY): CODE, CODE`.
Every original ordered reason/context/index and all same-report conflict peers
survive, including reason-excluded records and unselected advisories. `findings`
stays `[]`; unknown entries remain unscoped without decisions. Full batch/native
evidence, accounting and conservative fix/removal blockers are unchanged.
Omitting ANY preserves all previous JSON/Markdown bytes, including ALL selection.

Every requested code must belong to the supported adapter vocabulary in the
unknown-reason table above. An unsupported code fails even alongside a matching
code. A supported code absent from the selected records is allowed alongside
a matching code; a collection with no matching entry fails. Malformed/empty
collections, invalid/unsupported codes, incompatible reason selectors and
missing/mismatched native selectors produce `InputError` / CLI exit **2**,
no stdout, value-free diagnostics and unchanged existing output. All inputs,
including unselected/opposite-side reports, are validated. The
[ANY-reason contract](../examples/delta/explain/reason-any-cases.json),
`python -m pytest tests/scandelta/test_reason_any.py` and

JSON/Markdown contracts.

An optional `--match-index INDEX` (library `explain_match_index=INDEX`)
selects **one original native match** within this same drilldown. It requires
explicit advisory, side and artifact ID. The index is zero-based in that side's
original Grype `matches` array; it is report-local and is never an index into
`unknown_findings`, a scope or an alias. Reordering a report changes its indexes.
The library accepts a nonnegative `int` (not `bool`, float or string); CLI syntax
is ASCII decimal digits only, without signs, whitespace, decimals or exponents.
`0` is valid if native match zero is an unknown entry matching all selectors.

The optional scalar, ALL or ANY reason selector intersects this selection: the
indexed entry must satisfy the requested membership rule, and every original
reason remains in the result. It never
falls back to a different same-ID entry. `unknown_filter` adds integer
`match_index` only when supplied; for example `{"side": "after", "artifact_id":
"native/~shared ID", "reason_code": "ambiguous_package_location", "match_index": 4}`.
Markdown adds `Native match index: 4`. The single selected entry retains its
original `unknown_index`, native source pointer, all reasons in order and every
same-report conflict peer, including unselected advisories and other duplicates.
`findings=[]`, no unknown scope/decision, complete batch evidence/accounting and
conservative fix/removal blockers are unchanged. Omission (library `None`)
preserves every previous JSON/Markdown byte, including reason-only drilldowns.

For the reason-filter command above, append `--match-index 4`: it selects only
unknown index **3**, source `/after_report/matches/4`, distinguishing it from the
identical native match **3**. All three original reasons and conflict pointers
**1, 3, 4, 6, 7, 8** survive. `--match-index 7` without a reason selects unknown
index **6** with its two original reasons; pairing it with
`--reason-code ambiguous_package_location` fails. A native index of **2** with
the shared artifact ID also fails, even though unknown index 2 has that ID:
native match 2 belongs to `other-artifact`.

Invalid/noninteger/negative/out-of-range indexes, missing selectors,
normalized-only, wrong-advisory/artifact and reason-mismatch selections return
`InputError` / CLI exit **2**, with no stdout, value-free diagnostics and
unchanged existing output. Unsupported or malformed reports, including
unselected/opposite-side records, still fail full validation. The
[match-index contract](../examples/delta/explain/match-index-cases.json),
`python -m pytest tests/scandelta/test_match_index.py` and
`python scripts/delta/verify_match_index.py` cover both sides, duplicate/differing
same-ID entries, zero, complete context and safe JSON/Markdown failures.

Unknown selection requires literal equality with `vulnerability.id`; aliases
select normalized rows only. Related advisory IDs, URLs and extension fields
are retained evidence, never inferred selectors. Thus an alias may select known
rows while an unknown record with a different native ID remains unselected in
the full batch output. Markdown includes a selected-unknown table and the same

## Reproduce tests and the optimization comparison

```sh
python -m pytest tests/scandelta
vulnwrench delta --help
python scripts/delta/verify_examples.py
python scripts/delta/verify_grype.py
python scripts/delta/verify_explain.py
python scripts/delta/verify_target.py
python scripts/delta/verify_package_path.py
python scripts/delta/verify_gates.py
python scripts/delta/compare_naive.py
```

`compare_naive.py` has 14 small, fixed, hand-labelled synthetic scenarios.
The baseline is raw `(VulnerabilityID, PkgName, InstalledVersion)` set
subtraction: intersection means persistent, additions introduced, removals
fixed. It has no aliases, inventory, scope or snapshot checks. A scenario is
correct only when its whole predicted classification set equals the expected
set. This measures this corpus's transition semantics, not population-wide
accuracy. False-fixed counts are removed baseline tuples / fixed new rows in
scenarios whose expected set contains no fixed transition. The separate-copy
scenario also measures a missed fix that this false-fixed metric doesn't cover.

The actual captured run is in [examples/delta/comparison.json](../examples/delta/comparison.json).
The raw baseline matched **3/14** scenarios and made **10** false-fixed claims;
vulnwrench delta matched **14/14**, with **0** false-fixed claims. This improvement
is the optimization goal; **there is no speedup claim**. The baseline lacks
many of the new semantics by design and does much less work.

In the captured run (Python 3.14.4, Linux x86_64) the median for the whole
14-case corpus was **0.007426 ms** for the baseline and **1.151417 ms** for
vulnwrench delta. Seven samples each execute the entire corpus 200 times, single
process. Parsing, file I/O, import, formatting and any scanner execution are
excluded; vulnwrench delta timing includes actual normalization, aliases, inventory
validation, classification, accounting and provenance hashing. Timings vary
on rerun and are descriptive, not performance guarantees. `--output FILE`
can capture a new experiment without modifying the committed measurement.

The test suite covers the labelled corpus plus CLI success/gate/failure,
missing database, incomplete inventory/report, paths, aliases, PyPI and scoped
npm mapping, duplicate records, nested BOMs, unsupported shapes, safe errors,
output protection and deterministic evidence.
No scanners, network, target code or package lifecycle hooks are used.

## Upstream relationship and limits

[Trivy #2603](https://github.com/aquasecurity/trivy/issues/2603) describes the
need to distinguish scan changes from advisory changes.
[Grype #3511](https://github.com/anchore/grype/issues/3511) is retained context,
not proof that current Grype lacks comparison/deduplication.
[CycloneDX CLI](https://github.com/CycloneDX/cyclonedx-cli) already offers
component diff. vulnwrench delta adds conservative vulnerability transition evidence
from these scoped inventories, explicit aliases and scanner/DB identities.
It neither replaces scanners nor claims unique functionality across the market.

MVP limits: Trivy schema 2 and pinned Grype 0.86.1 only, npm/PyPI only, JSON only,
strict scoped library BOMs; no other Grype versions, OSV parser, OS packages,
containers/layers, remediation, online advisory
lookup, automatic aliases, SBOM generation, authenticity verification, severity
gate, or guarantees of vulnerability completeness. The test corpus is
synthetic; real scanner binaries and live advisory databases were not run.
